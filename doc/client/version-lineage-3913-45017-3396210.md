# 客户端版本谱系：3913 → 45017 → 3396210

本文按实际客户端文件对比三代 EVE 客户端，说明 **45017（Trinity 4.10）处在什么技术状态**。结论基于 2026-11-02 对 `M:\EVE-LOCAL\inputs\` 下三个客户端目录的直接读取，不引用现代 EVE 的二手资料。

## 一句话结论

**45017 不是"缩水版现代客户端"，也不是"加料版 3913"，而是 CCP 客户端从 RMR 单体 32 位体系迁往现代模块化体系的换轨点：结构性前身已经全部出现，但每一项都只完成了一半。**

具体说：Python 已从 2.4 跨到 2.5（还没到 2.7）；代码容器已引入 ZIP + `.pyj`（但只有 `lib`/`stdlib` 换了，`script` 仍走旧 pickle）；资源已从单体 `.stuff` 走向分卷 + 签名清单（但还不是内容寻址）；引擎已拆出独立 Python DLL 与 `db.dll`（但仍是 32 位、仍只有 DX9）。因此 3913 的工具不能直接用于 45017，3396210 的 `.fsdbinary`/`code.ccp` 经验也不能套到 45017 上。

## 三代客户端的技术档案

### 3913：RMR 时代的单体 32 位客户端

- 32 位 PE，`exefile.exe` 只有 131 KB，主要逻辑在 `trinity.dll`（3.8 MB）与 `blue.dll`（2.3 MB）里；Python 解释器不在独立 DLL 中，随主引擎内置。
- 代码是**单个** `script\compiled.code`：pickle 协议 1 的 373 项列表，每项是模块路径 + 一段 marshal code object + mtime。模块本身是 Python 2.4 字节码（`dist/manifest.json` 记 `pyc_magic=6df20d0a`，`container_md5=36e18ef3…`）。
- `lib\` 下同时发行 `.py` 源码与 `.pyo`；`.pyo` 的 magic 为 `3bf2`（Python 2.3），属旧编译产物，运行时仍以 2.4 容器为准。**不要把 `.pyo` 的 2.3 magic 当成客户端运行时版本。**
- 资源是 11 个单体 `.stuff`（约 1.3 GB），没有文件级清单；启动时按卷加载。
- 没有语音、没有独立语言包、没有 `manifest.dat`、没有 `bulkdata`。

### 45017：Trinity 4.10 的"半迁移"客户端

- 仍是 32 位，但 Python 变成独立 `python25.dll`；`_trinity.dll` 之外新增 `boost_python.dll`、`db.dll`、`NetUtil.dll`、`_ctypes.pyd`、`pyexpat.pyd`，并引入 Vivox 语音与 OpenAL（`wrap_oal.dll`）。
- `script\compiled.code` 仍是**旧式 pickle 容器**，但已升级到协议 2，顶层从"模块列表"变成"分区字典"：
  - `cargo`：468 个 Web 资源（`wwwroot:/...`，css/img 等）；
  - `code`：436 个 `(模块路径, (打包字节, 整数))`；
  - `timestamp`、`preprocessed` 两个元数据键。
- **第一次出现 ZIP + `.pyj`**：`lib\lib.ccp`（23 项）与 `lib\stdlib.ccp`（226 项）都是标准 ZIP，条目名 `*.pyj`。条目内容不是裸 zlib，而是 **RC4(zlib(pyc))**：先 RC4 解密，再 zlib 解压，得到 Python 2.5 pyc；同一套 RC4 也用于 `compiled.code` 的 marshal 载荷。固定 `93 8e` 只是同一明文前缀（zlib `78 9c`）经同一 RC4 密钥流后的结果。**45017 的加密层与现代 `.pyj` 的裸 zlib 不同。**
- 资源侧第一次出现 35 个分卷、8 个语言包与 `manifest.dat` 完整性清单；`manifest.dat` 用 UTF-16LE 存路径，逐文件带 128 字节摘要块，并记录 `script:/compiled.code`、`root:/bin/*.dll`、`lib:root:/lib/*.ccp`。这是从"信任安装目录"到"逐文件校验"的转折。
- **没有现代 FSD。** 客户端不含 `_pyfsd.dll`；对 35 个 `.stuff` 与 35 个 `bulkdata\*.cache` 做内容扫描，`fsdbinary` / `FsdDict` / `FsdObject` / `_pyfsd` / `staticdata` 五个标记均为 0 命中。静态数据走 `bulkdata\*.cache`：字节流以 blue.marshal 魔数 `~` 开始，紧随 `TUPLE_2`，样本首键为 `config.BulkData.dgmtypeattribs`、`config.BulkData.bptypes`、`config.BulkData.categories`。
- 图形资源按种族/舰船/空间站拆成 15 个 `resDX9*` 包（1.47 GB），说明 Trinity 的 premium DX9 内容管线已经落地，但引擎仍只有 DX9。
- 启动配置从 `boot.ini` 拆成 `boot.ini`（服务器/端口/edition）+ `common.ini`（版本/构建/代号/加密包/分支）。`cryptoPack=CryptoAPI` 说明客户端已带 CryptoAPI 加密上下文；本项目服务端走的是 `Placebo`（见 `doc/platform/architecture.md` 与 `crates/eve-proto/src/handshake.rs`）。

### 3396210：现代 64 位、内容寻址、双图形后端客户端

- 64 位 PE；`exefile.exe` 约 1 MB，图形拆成 `_trinity_dx11.dll` 与 `_trinity_dx12.dll` 两套，另有 DLSS、XeSS、FidelityFX 与 `GFSDK_Aftermath`。
- Python 2.7（`python27.dll`），代码统一进**单个** `tq\code.ccp`：ZIP，12,528 个 `.pyj`，每个 `.pyj` 是 zlib deflate 的 Python 2.7 pyc（magic `03f30d0a`）。内嵌路径带 CI 构建目录（`V24.01`）。
- 资源改为内容寻址：`ResFiles\` 下 128,780 个文件，按哈希前缀分两级目录；`index_tranquility.txt` 每行 6 个字段（路径、两级哈希、原始大小、压缩大小、CRC）。这与 45017 的 `manifest.dat` 是同一思路的成熟形态。
- 静态数据分成两层：`bin64\staticdata\` 下 159 个 `*Loader.pyd` 负责把 `res:/staticdata/*.fsdbinary`（149 个，`agenttypes`/`archetypes`/`accountingentrytypes` 等）读成 Python 对象，`_pyfsd.dll`（364,680 B）提供 `FsdDict`/`FsdList`/`FsdObject`/`FsdUnsignedIntegerKeyMap` 运行时；另有 `tq\res\planetResources.pickle`、`carbon.json` 组件版本清单、`eve_public_grpc_client.pyd`（gRPC/ESI 时代外围服务）。
- 客户端目录里大量 `.bak` / `.original` 说明这是**已打补丁的现网部署**，不是纯零售快照；用于对照格式可以，用于取值不行。

## FSD：现代客户端独有，3913 / 45017 都没有

结论：**45017 不含现代客户端的 FSD。** 判据不是"没找到同名文件"，而是整条链路都不存在：

| 判据 | 3913 | 45017 | 3396210 |
|---|---|---|---|
| `_pyfsd.dll` | 无 | 无 | 有，364,680 B；含 `FsdDict`、`FsdList`、`FsdObject`、`FsdUnsignedIntegerKeyMap` 运行时类 |
| `res:/staticdata/*.fsdbinary` | 无 | 无 | 149 个 |
| 文件/`.stuff`/`.cache` 中的 `fsdbinary`、`FsdDict`、`FsdObject`、`_pyfsd`、`staticdata` 标记 | 无 `fsd` 文件名，无加载器 | 70 个文件（35 `.stuff` + 35 `.cache`）全部 0 命中 | 索引与 DLL 中大量出现 |
| 静态数据载体 | 客户端包内数据 | `bulkdata\*.cache`（35 个，blue.marshal） | `.fsdbinary` + `*Loader.pyd` |

45017 时代客户端静态数据走的是 **BulkData 缓存**：`bulkdata\*.cache` 是 blue.marshal 流（魔数 `~`，紧随 `TUPLE_2`，首键如 `config.BulkData.dgmtypeattribs`、`config.BulkData.bptypes`）。`db.dll` 是 OLEDB 访问层（`DB::NSession::Execute`、`DBTYPE_*` 等），也不是 FSD。

现代客户端才把静态数据换成 schema 化的 `.fsdbinary`，由 `_pyfsd.dll` 读取；两者格式、加载方式、Python API 都不同，不能互读：

- 45017：`config.BulkData.*` + blue.marshal + 客户端自定义缓存；
- 3396210：`res:/staticdata/*.fsdbinary` + `_pyfsd.FsdDict/FsdObject` + `*Loader.pyd`。

因此，给 45017 改表/补本地化不能用现代 `.fsdbinary` 工具链；要在 45017 上支持 FSD 属于**新增格式支持**，不是"打开客户端里已有的 fsd"。

## 45017 到底处于什么状态

把上面三代放在一条线上，45017 的位置可以拆成七个"半迁移"：

1. **运行时：2.4 → 2.5，未到 2.7。**
   3913 的字节码是 2.4；45017 换成 2.5 并把解释器拆成 `python25.dll`；2.7 要到现代客户端才出现。45017 的字节码/容器必须按 Python 2.5 处理。

2. **代码容器：ZIP 已引入，但只覆盖 `lib`/`stdlib`。**
   45017 的 `lib.ccp`/`stdlib.ccp` 已经是现代 `code.ccp` 的同款 ZIP + `.pyj` 外形；但游戏主体 `script\compiled.code` 仍是 3913 式 pickle 容器。现代客户端把两者合并成一个 30 MB 的 `code.ccp`，45017 还处在"新容器试水、旧容器继续用"的并行期。

3. **`.pyj` 编码：RC4 + zlib，外面多了一层加密。**
   45017 的 `.pyj` 与 `compiled.code` 载荷先 RC4 加密，再在解密后 zlib 解压；固定 `93 8e` 是同一 zlib 明文前缀经同一密钥流后的外观。密钥是 `blue.dll` 里 140 字节 SIMPLEBLOB 的 16 字节会话密钥（`blob[12:28]` 反转）。现代 `.pyj` 是裸 zlib；**同一个扩展名，两代编码**，这是 45017 最容易被误判的地方。

4. **资源：从单体走向分卷 + 清单，但还不是内容寻址。**
   3913 是 11 个单体 `.stuff`；45017 变成 35 个分卷 + `manifest.dat` 逐文件摘要；3396210 才把文件摊平成 `ResFiles` + `index_*.txt`。45017 是"分卷 + 完整性校验"的起点，不是终点。

5. **引擎与外围：拆分完成，但仍是 32 位 / DX9。**
   独立 Python DLL、`boost_python`、`db.dll`、`NetUtil.dll`、Vivox 语音都在 45017 出现；64 位、DX11/DX12、DLSS/XeSS 要等到现代客户端。45017 是"功能模块化已开始、位宽与图形后端未换代"的状态。

6. **内容管线：DX9 premium 资源按种族分卷。**
   15 个 `resDX9*`、1.47 GB，说明 Trinity 扩展包的高端纹理/舰船/空间站内容已经按种族和场景拆包；这是 3913 单一 `resTextures.stuff` 所没有的规模。

7. **协议：Trinity 世代的 LLV 已经在位。**
   本项目服务端按 45017 固定：LLV magic `170472`、macho version `182`、boot `4.10`、build `45017`、`LIVE@ccp`（`crates/eve-proto/src/llv.rs`）。3913 属于上一个协议世代，现代客户端则已在该协议之外叠加 gRPC/ESI 等外围服务。**45017 是这条协议线的唯一定点，不能用 3913 或现代的数值替代。**

## 对本项目的直接约束

- **45017 是唯一基准。** 服务端 LLV、macho 帧、marshal 字符串表、客户端补丁目标全部锁定 4.10/45017；`AGENTS.md` 的"零售版本优先"在这里等价于"以 45017 客户端文件为准"。
- **3913 的 `compiled.code` 工具不能直接用于 45017。** 两者虽然都叫 `compiled.code`，但一个是 pickle v1 的模块列表，一个是 pickle v2 的分区字典；45017 的载荷还多一层 RC4。3913-code 仓库的 `extract_compiled_code.py` / `build_compiled_code.py` 只能处理 3913；45017 有自己的解包工具（`EVE-Online-45017-code/tools/extract_compiled_code.py`）。
- **3396210 的经验不能套用。** `.fsdbinary`、`code.ccp` 的 zlib `.pyj`、Python 2.7、64 位、DX12 都是现代客户端的事实，不是 45017 的事实。现代客户端只可作为"容器演进方向"的参照，不可作为取值或格式依据。
- **客户端补丁的当前阻塞点**是重打包/签名：解码已解决（RC4 密钥 + zlib + pickle v2），但还没有可签名的重打包工具。在它落地前，`doc/client/client-45017.md` 里的"只改显示文本"流程不能执行；基线仓库已完成解包与反编译。

## 未确认项

- 45017 的重打包/签名方案尚未实现；解包侧已确认：RC4（16 字节密钥，`blue.dll` SIMPLEBLOB）+ zlib + Python 2.5 marshal/pyc。
- 3913 的 LLV / macho 具体数值未取（本项目只实现 45017 服务端，未对 3913 做握手比对）。
- 3396210 的协议细节未核对；本文只对比客户端文件形态，不声称其 machoNet 版本。
- 3396210 的 `.fsdbinary` 在 `ResFiles` 中是压缩存储（索引给出原始大小与压缩大小），具体压缩算法未解码；这不影响"3913/45017 无 FSD"的结论。
- 45017 的 `manifest.dat` 每文件 128 字节摘要块的具体算法（SHA-1/RSA 签名/其它）未确认；本文只使用"逐文件摘要清单"这一事实。

## 复现要点

- 读 `boot.ini` / `common.ini`：直接文本读取即可确认版本、构建、代号、加密包。
- 读 `script/compiled.code`：Python 3.11 用 `pickle.Unpickler(..., encoding='bytes')`；3913 得到 373 项列表，45017 需跳过 `\x80\x02J<magic>T<u32 len>` 头再反序列化。
- 读 `lib/*.ccp` / `code.ccp`：`zipfile.ZipFile`；45017 条目先 RC4（密钥见 `blue.dll`）再 `zlib.decompress`，得到 pyc；3396210 条目直接 `zlib.decompress` 后是 pyc。
- 判断位数：PE 头 `e_lfanew + 4` 的 machine 字段，`0x14c` = x86，`0x8664` = x64。
- 判断 Python 版本：pyc/容器 magic 低 16 位，`0xf23b`=2.3、`0xf26d`=2.4、`0xf2b3`=2.5、`0xf303`=2.7。
